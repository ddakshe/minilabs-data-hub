# 과태료 금액 구조화 — 설계안

> 목적 두 가지 — ① 「내가 신고해서 모인 과태료 총액」, ② `rate` 동네에서도 실제 포상금 **금액** 보여주기.
> 현재 스키마로는 둘 다 불가능하다. 무엇을 바꿔야 하는지와 비용을 적는다.
> **미승인 초안이다.** `report-reward/` 데이터에는 아직 반영하지 않았다.
> 실측 기준 2026-09-11, verified 57곳(서울 25 · 경기 31 · 홍천 1).

---

## 1. 막혀 있는 지점

| 사실 | 수치 |
|---|---|
| `examples` 행 | 232행 |
| 그중 `fineWon` 이 있는 행 | **84행 (36%)** |
| 포상금 금액을 **전혀** 못 만드는 동네 (`rate` + `examples` 없음) | **19곳** |
| `dumping.method` 분포 | `table` 36 · `rate` 20 · `fixed` 1 |
| 과태료 구간표 형태(품목별 아님) | 4곳 (평택·김포·광주·양평) |
| `tableOnly` (금액표 못 엶) | 1곳 (고양 41280) |

**문제 1 — `rate` 동네 19곳은 곱할 대상이 없다.**
「과태료의 20%」만 있고 과태료 금액이 없으면 앱은 「20%예요」라고밖에 못 쓴다.
강북 10% · 노원 20% · 은평 50/40% · 서대문 20% · 강서 20% · 금천 40/20% · 영등포 20% · 강남 50/20% ·
수원 20% · 의정부 20% · 광명 20% · 안산 80% 이내 · 하남 20% · 파주 40% · 이천 40% · 안성 40% · 여주 40% · 연천 40%.
(관악은 유형별 비율이라 라벨만으로 표는 되지만 금액은 역시 없다.)

**문제 2 — `guide.json` 의 `penalty` 는 숫자가 아니다.**

```
parking-six   → "승용차 기준 어린이보호구역 12만 원, 소화전 8만 원, … (승합차는 1만 원 더)"
dumping-trash → "폐기물관리법에 따라 과태료가 부과돼요"
```

문장이라 합산 불가. **17개 중 7개는 `penalty: null`.** 무단투기 밖 카테고리는 총액에서 통째로 빠진다.

## 2. 근거 — 과태료는 조례가 아니라 시행령이 정한다

무단투기 과태료는 **「폐기물관리법 시행령」 제38조의4 별표 8** 로 전국 동일하다.
조례는 *포상금* 만 달리 정할 수 있고 과태료는 못 바꾼다. 원문 확인(2026-03-24 공포, MST 284591):

### 법 제8조제1항·제2항 — 무단투기 (위반 횟수와 무관하게 동일)

| 표준 라벨 | 과태료 |
|---|---|
| 담배꽁초·휴지 등을 버린 경우 | 50,000 |
| 비닐봉지·보자기에 담아 버린 경우 | 200,000 |
| 휴식·행락 중 쓰레기를 버린 경우 | 200,000 |
| 차량·손수레로 버린 경우 | 500,000 |
| 사업활동 폐기물을 버린 경우 | 1,000,000 |
| 사업활동 폐기물을 매립한 경우 | 1,000,000 |
| 그 밖의 폐기물을 매립한 경우 | 700,000 |
| 사업활동 폐기물을 소각한 경우 | 1,000,000 |
| 그 밖의 폐기물을 소각한 경우 | 500,000 |

### 법 제15조제1항·제2항 — 배출방법 위반 (**1·2·3차 가중**)

| 위반 | 1차 | 2차 | 3차 |
|---|---|---|---|
| 단독·연립·아파트 주거생활 관련 배출 | 100,000 | 200,000 | 300,000 |
| 같은 건물·토지 입주자 개별 배출(사업활동) | 200,000 | 300,000 | 500,000 |
| 같은 건물·토지 입주자 공동 관리 배출(사업활동) | 500,000 | 700,000 | 1,000,000 |

**검증** — 조례가 과태료를 같이 인쇄한 6곳(중구·동대문·도봉·동작·용산·성남)은 **전 행이 위 표와 일치**했다.
중구 별표 4에는 단위 표기가 없었는데 과태료 칸(50/200/100/500/1,000)이 이 표와 맞아 천원 단위로 확정했다.

### 전국 표로 덮이지 않는 것

| 라벨 | 왜 |
|---|---|
| 대형폐기물을 버린 경우 | **별표 8 에 해당 행이 없다.** 조례가 자체로 정한 개념(중구는 10만원으로 인쇄) |
| 규격봉투 미사용·분리배출 위반 / 혼합배출·배출시간 위반 / 주거용 분리배출 위반 | 법 제8조가 아니라 **제15조** → 가중 적용 |
| 반려동물 배설물을 방치한 경우 (송파) | 폐기물법 과태료 표에 없음 |
| 그 밖의 위반 (과태료 50만원 이상) (가평) | 품목이 아니라 구간 |

→ **전국 표는 기본값일 뿐, 조례에 인쇄된 값이 언제나 우선이어야 한다.**

## 3. 설계

### 변경 A — `report-reward/fines.json` 신설

전국 공통 과태료를 **한 번만** 둔다. 229곳에 같은 숫자를 복제하지 않고, 시행령 개정 시 이 파일만 고친다.

```json
{
  "updatedAt": "2026-09-11",
  "sources": [
    { "kind": "시행령", "title": "폐기물관리법 시행령", "articles": ["제38조의4", "별표 8"],
      "lawMst": "284591", "promulgatedAt": "2026-03-24",
      "url": "https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=284591" }
  ],
  "dumping": [
    { "label": "담배꽁초·휴지 등을 버린 경우",     "fineWon": 50000,   "lawRef": "법 제8조제1항" },
    { "label": "비닐봉지·보자기에 담아 버린 경우", "fineWon": 200000,  "lawRef": "법 제8조제1항" },
    { "label": "휴식·행락 중 쓰레기를 버린 경우",  "fineWon": 200000,  "lawRef": "법 제8조제1항" },
    { "label": "차량·손수레로 버린 경우",          "fineWon": 500000,  "lawRef": "법 제8조제1항" },
    { "label": "사업활동 폐기물을 버린 경우",      "fineWon": 1000000, "lawRef": "법 제8조제1항" },
    { "label": "사업활동 폐기물을 매립한 경우",    "fineWon": 1000000, "lawRef": "법 제8조제2항" },
    { "label": "그 밖의 폐기물을 매립한 경우",     "fineWon": 700000,  "lawRef": "법 제8조제2항" },
    { "label": "사업활동 폐기물을 소각한 경우",    "fineWon": 1000000, "lawRef": "법 제8조제2항" },
    { "label": "그 밖의 폐기물을 소각한 경우",     "fineWon": 500000,  "lawRef": "법 제8조제2항" },

    { "label": "주거용 분리배출 위반", "fineWon": 100000,
      "repeatWon": [100000, 200000, 300000], "lawRef": "법 제15조" },

    { "label": "대형폐기물을 버린 경우", "fineWon": null, "lawRef": null,
      "note": "시행령 별표 8에 해당 행이 없어요. 지자체가 조례로 정해요." }
  ]
}
```

- **`kind: "시행령"`** — 지금 `sources[].kind` 는 `조례 | 규칙` 만 허용한다. 시행령을 region 파일에 못 넣는 이유이자 별도 파일로 빼는 이유다. 월간 개정 감지도 자치법규(`ordinId`/`mst`)와 주기가 달라 따로 봐야 한다.
- **`repeatWon`** — 제15조는 1·2·3차로 가중된다. `fineWon` 은 1차값, 전체는 `repeatWon`.
- **`fineWon: null` 허용** — 전국값이 **없는** 것을 0이나 추정치로 채우지 않는다.

### 변경 B — 조인 키는 **표준 라벨** (별도 키를 넣지 않는다)

2026-09-11 라벨 정리로 `item` 문자열이 **101종 → 45종**으로 수렴했고 24종은 2곳 이상이 공유한다.
따라서 `fineKey` 같은 새 필드 없이 **`item` 라벨 자체를 조인 키로 쓴다.** region 파일에 추가 필드가 없다.

**대신 라벨이 사실상 키가 되므로 검증기가 지켜야 한다.** 한 글자만 달라도 조인이 조용히 끊기고 앱에서 금액이 사라진다.

- `examples[].item` / `rates[].item` 이 `fines.json` 의 `label` 에 없으면 **⚠ 경고**
  (지역 고유 항목은 정상이므로 실패시키지 않는다)
- `fines.json` 의 `label` 끼리 중복 금지

### 변경 C — `examples` 의 두 가지 의미를 분리

지금 `examples` 가 **서로 다른 두 관계**를 같은 모양으로 담고 있다.

| | 뜻 | 곳 |
|---|---|---|
| 품목형 | 「담배꽁초 투기 → 1만원」 | 32곳 |
| **구간형** | 「과태료가 100만원 이상이면 → 20만원」 | **4곳** (평택·김포·광주·양평) |

구간형의 `item: "과태료 100만원 이상"`, `fineWon: 1000000` 은 *그 유형의 과태료*가 아니라 **구간 하한**이다.
앱이 구분하지 못하면 「과태료 100만원 이상이라는 투기 유형」이라는 없는 항목을 그린다.

```json
"dumping": { "method": "table", "basis": "item" }       // 품목형 (기본값, 생략 가능)
"dumping": { "method": "table", "basis": "fineRange" }  // 구간형 — fineWon 은 구간 하한
```

### 변경 D — `guide.json` 에 구조화 금액 추가

무단투기 밖 카테고리도 총액에 들어가려면 숫자가 필요하다. `penalty` 문장은 표시용으로 **그대로 두고** 옆에 붙인다.

```json
"penalty": "승용차 기준 어린이보호구역 12만 원, 소화전 8만 원, …",
"penaltyAmounts": {
  "kind": "fine",
  "rows": [
    { "label": "어린이보호구역 (승용차)", "fineWon": 120000 },
    { "label": "소화전 (승용차)",        "fineWon": 80000  },
    { "label": "교차로·버스정류소·횡단보도·인도 (승용차)", "fineWon": 40000 }
  ],
  "note": "승합차는 1만원 더"
}
```

| kind | 뜻 | 해당 |
|---|---|---|
| `fine` | 과태료 금액이 정해져 있다 | 불법주정차 3종, 무단투기 |
| `criminal` | 형사처벌 — 과태료 아님 | 난폭운전, 불법촬영 |
| `variable` | 위반 종류마다 달라 단일 금액이 없다 | 교통법규 위반, 환경오염 |
| `none` | 금전 제재가 없다 | 층간소음, 킥보드 방치 |

`kind != "fine"` 이면 `rows: null`. **추정치를 채우지 않는다.**

## 4. 앱이 금액을 만드는 규칙

`regions/{code}.json` + `fines.json` 을 **라벨로** 조인한다. 우선순위는 **조례 > 전국표**.

```
한 행의 과태료 =
  1) examples[].fineWon 이 있으면 그 값       (조례가 직접 인쇄한 값 — 최우선)
  2) 없으면 fines.dumping 에서 같은 label 의 fineWon
  3) 둘 다 없으면 null → 금액을 쓰지 않는다 (「유형별로 달라요」)

포상금 =
  table → examples[].rewardWon 그대로
  fixed → fixedWon
  rate  → 위 과태료 × rates[].rate
          rates[].item 이 「모든 무단투기 유형」이면 fines.dumping 9행 전체에 곱해 표를 만든다
          「그 밖의 무단투기」면 같은 파일의 다른 rates 행이 집은 라벨을 뺀 나머지에 곱한다
```

이 규칙 하나로 **19곳이 「20%예요」에서 「담배꽁초 1만원 · 차량 10만원 …」으로 바뀐다.**

**곱셈만으로는 틀리는 곳이 두 종류 있다 — 필드가 더 필요하다.**

- **최저 지급액.** 강북구는 「과태료의 10%, **최저 3만원**」이라 담배꽁초 5만원 × 10% = 5천원이 아니라 3만원이다.
  지금 이 정보는 `note` 에 문장으로만 있다. → **`caps.minWon` 필요**(강북·양평·동대문 등).
- **상한형 비율.** 안산시는 「80% **이내**」다. 확정값처럼 곱하면 과대 표시된다.
  라벨에 「(80% 이내)」를 남겼지만 문자열이라 계산에 못 쓴다. → **`rates[].cap: true` 필요**.

## 5. 두 총액은 앱이 쌓는다 — 허브는 단가만 준다

허브는 「건당 얼마」까지만 책임진다. 누적은 앱 로컬 상태다. 다만 세 가지를 설계에 박아야 한다.

**① 신고 시점 금액을 스냅샷으로 저장한다.**
조례·시행령이 개정되면 과거 신고 금액이 소급해 바뀐다. 누적은 `reportedAt` 당시 값을 **복사해서** 저장한다.
매번 현재 표로 재계산하면 작년 기록이 조용히 달라진다.

**② 「모인 과태료 총액」은 실적이 아니라 추정이다.**
앱은 과태료가 실제로 부과됐는지 알 수 없다. 신고했다고 다 부과되지 않는다 —
증거 부족·행위자 미특정·이의제기로 빠지는 사유가 조례마다 명시돼 있고,
지자체 상당수가 「과태료를 부과한 경우에만 지급」이라고 못박는다.

| 상태 | 의미 | 총액 반영 |
|---|---|---|
| `reported` | 신고함 | 「신고한 건」 카운트에만 |
| `confirmed` | 과태료 부과·포상금 수령을 사용자가 확인 | **금액 총액에 반영** |

헤드라인을 `reported` 로 만들면 「내가 세금 340만원 모았어요」가 사실이 아닐 수 있다.
`confirmed` 기준으로 하고 `reported` 는 「처리 대기 N건」으로 따로 보여주길 권한다.

**③ 법정 기준액과 실제 부과액은 다르다.**
별표 8 일반기준에 감경 조항이 있다(질서위반행위규제법 대상자·과실·즉시 시정 → 1/2 범위 감경).
`fineWon` 은 **기준액**이므로 「보통 5만원」으로 쓰고 「5만원 확정」으로 쓰지 않는다.

| `guide.json` `penaltyAmounts` | 17항목 중 금액이 실재하는 건 4~5개, 나머지는 `kind` 만 |
| 기존 57곳 | **백필 불필요** — 라벨 조인이라 손댈 게 없다. 어긋난 라벨만 검증 경고로 잡아 고친다 |
| `basis: "fineRange"` 표시 | 4곳 |
| `caps.minWon` 채우기 | 조례 재확인 필요한 곳 소수(강북·양평·동대문 등) |
| `rates[].cap` | 1곳(안산) |
| 검증기 | 위 6개 규칙 |
| 남은 172곳 | 수집 시 표준 라벨을 그대로 쓰면 추가 비용 없음 |

**남은 172곳을 채우기 전에 하는 게 싸다.** 나중에 하면 229곳을 두 번 만진다.
다만 `_work`(조례 원문 재료) 수집은 스키마와 무관하므로 먼저 돌려둬도 손해가 없다.

## 8. 결정이 필요한 것

1. **`fines.json` 을 따로 둘 것인가, `guide.json` 안에 넣을 것인가?**
   따로 두기를 권한다 — 출처가 시행령이라 개정 감지 주기가 자치법규와 다르고, `guide.json`(25KB)을 안 건드리는 쪽이 앱 캐시에 유리하다.
2. **조인을 앱이 할 것인가, 빌드가 미리 풀어줄 것인가?**
   앱 조인을 권한다. 빌드가 풀면 파생값이 커밋에 섞여 조례 원문과 구분이 안 된다.
   (대안: `regions/{code}.resolved.json` 생성 — 파일 수 2배)
3. **`caps.minWon`·`rates[].cap` 을 이번에 같이 넣을 것인가?**
   금액을 보여주기 시작하면 바로 필요하다. 같이 넣기를 권한다.
4. **「모인 과태료 총액」을 `confirmed` 기준으로 할 것인가?** §5-② 참고. 제품 결정이다.
